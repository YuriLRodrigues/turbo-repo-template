# CLAUDE.md

Guidance for Claude Code in this monorepo. Each app has its own `CLAUDE.md` with the details; this one is what holds
everywhere.

## What this is

A full-stack template on Turborepo and npm workspaces:

| Workspace             | What                                                                                         | Port |
| --------------------- | -------------------------------------------------------------------------------------------- | ---- |
| `apps/api`            | NestJS 12 + Drizzle 1.0, clean architecture; identity complete; `notes` as the example       | 3500 |
| `apps/web`            | Next.js 16 static export: signed-in shell, auth screens, the notes screen, charts gallery    | 3501 |
| `apps/landing`        | a minimal product page (static export) with the basic SEO                                    | 3502 |
| `packages/ui`         | the neutral design system: tokens, primitives (Base UI + shadcn anatomy), charts, appearance | -    |
| `packages/api-client` | the API client generated by Orval, with the fetch mutator (refresh-and-retry, Web Locks)     | -    |
| `packages/utils`      | pure helpers: `cn`, money, numbers, dates                                                    | -    |
| `packages/config`     | ESLint (including the layer rules of the API), TypeScript and Prettier presets               | -    |

The `notes` context (API) and the notes screen (web) are the reference implementations: when adding something, find
the closest example there and follow it. Patterns are in `docs/patterns/`; the numbered rules of the product in
`docs/business-rules.md`.

## Commands (from the root)

```bash
npm install
npm run dev               # API (PGlite embedded, no .env needed) + web
npm run dev:landing       # the product page
npm run lint:check        # ESLint in every workspace (npm run lint fixes)
npm run format:check      # Prettier (npm run format writes)
npm run typecheck
npm test                  # unit + integration of every workspace
npm run test:e2e          # e2e of the API (on PGlite)
npm run build
npm run contrast          # contrast of every text token, both themes, every accent
npm run api:openapi       # writes apps/api/openapi.json from the code
npm run api:client        # regenerates packages/api-client/src/gen from it
npm run db:generate -- --name <kebab-name>   # a migration from the schema diff
```

Run a script of one workspace with `-w`: `npm test -w api`, `npm run screenshots -w web`.

## Before saying a change is done

`npm run lint:check`, `npm run format:check`, `npm run typecheck`, `npm test`, `npm run test:e2e` and `npm run build`,
all green. When a route changed: `npm run api:openapi` and `npm run api:client`, and commit `openapi.json` and
`src/gen` with the change. When the schema changed: a migration from `db:generate`, and `db:generate` answering "No
schema changes" afterwards. When a token or a color changed: `npm run contrast`. When a screen changed: the screenshots
(`docs/patterns/web/testing.md`).

## Rules everywhere

1. Code, comments, docs, commit messages and user-facing copy in English. Exact dependency versions (`.npmrc` has
   `save-exact`); a new dependency goes to the workspace that uses it.
2. Conventional Commits, checked by commitlint on `commit-msg`; the scope is the workspace or the area
   (`feat(api): ...`, `fix(web): ...`, `chore(deps): ...`). Hooks run lint-staged per workspace: never skip them with
   `--no-verify`; fix what they report.
3. The business rules live in the API, in pure functions of the domain, cited by number. The apps show the result.
4. The web app talks to the API only through `@workspace/api-client`; `src/gen` is never edited by hand.
5. A color, a radius or a shadow is a token of `packages/ui/src/styles/tokens.css`; components use roles.
6. Charts use `@workspace/ui/charts` (Recharts), never hand-drawn SVG.
7. Nothing scrolls through a raw `overflow-auto`/`overflow-scroll` class: `ScrollArea` or `ArrowScrollArea` (lint).
8. A grid track or a flex item that holds something wide has a size (`minmax(0, 1fr)`, `min-w-0`):
   `docs/patterns/web/layout.md`.
9. Never write or edit a migration by hand.

## Skills

Project skills in `.claude/skills/`:

- `new-api-context`: a bounded context in the API, end to end (domain, infra, HTTP, tests, contributor).
- `new-api-route`: one more use case and route in an existing context.
- `new-web-screen`: a screen of the web app on the generated client (list, form, states, navigation, tests).
- `regenerate-api-client`: after a route changed, export the document and regenerate the client.
- `pre-pr-checklist`: everything to run and check before opening a pull request.
- `rename-project`: give the template its product name.
