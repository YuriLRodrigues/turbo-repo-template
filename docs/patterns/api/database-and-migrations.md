# Database and migrations

Postgres through Drizzle ORM 1.0. The schema is TypeScript in `src/infra/database/drizzle/schema/`, one file per
table, all exported from `schema/index.ts`.

```ts
export const notes = pgTable(
  'notes',
  {
    id: uuid('id').primaryKey(),
    userId: uuid('user_id')
      .notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
    title: varchar('title', { length: 120 }).notNull(),
    body: text('body'),
    pinned: boolean('pinned').notNull().default(false),
    archivedAt: timestamp('archived_at', { withTimezone: true }),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => [index('notes_user_id_pinned_updated_at_idx').on(table.userId, table.pinned, table.updatedAt)],
)
```

Conventions:

- Schema files import each other with **relative** paths: drizzle-kit loads them outside of Nest and does not read
  the tsconfig paths.
- Ids are `uuid`, generated by the domain (`UniqueEntityId`), never by the database.
- Every table that belongs to a person points to `users` by a column named `user_id`, with `onDelete: 'cascade'`. The
  name matters: `isMissingUserViolation` reads the constraint to answer 401 for a write of a deleted account.
- Instants are `timestamp with time zone`; days without a time are `date` (`mode: 'string'`); money is `bigint` of
  cents (`mode: 'number'`).
- An enum of the domain (`as const` list) becomes a `pgEnum` from that same list. A list that grows often (the values
  of the design system) is plain `varchar` checked by the domain instead, so it grows without a migration.
- An index follows the `where` + `order by` of the list it serves.

## Migrations

**Never write or edit a migration by hand.** Change the schema, then:

```bash
npm run db:generate -- --name add-note-color   # from the root: drizzle/<timestamp>_add-note-color/migration.sql
```

Read the SQL it wrote. Commit the folder with the code that needs it.

- Development without `DATABASE_URL`: the embedded database applies the pending migrations on every boot
  ([embedded database](./embedded-database.md)).
- With a Postgres: `npm run db:migrate` (drizzle-kit) or, from the build, `npm run db:migrate:prod -w api`
  (`dist/infra/database/migrate.js`, no dev dependencies needed).
- Before a change is done, `npm run db:generate` must answer "No schema changes".
- Until the first production deploy it is fine to delete `apps/api/drizzle/` and generate one `init` migration again.
