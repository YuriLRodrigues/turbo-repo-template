# Languages (i18n)

The landing (`apps/landing`) speaks Brazilian Portuguese, English and Spanish. The person picks the language with the
switcher in the header (or the pill in the footer); nothing is guessed from the browser, and nothing redirects. The web
app (`apps/web`) is in English only.

| Language       | Address | `<html lang>` | `og:locale` |
| -------------- | ------- | ------------- | ----------- |
| `pt` (default) | `/`     | `pt-BR`       | `pt_BR`     |
| `en`           | `/en/`  | `en`          | `en_US`     |
| `es`           | `/es/`  | `es`          | `es_ES`     |

## Map

```
apps/landing/
  i18n/config.ts              locales, defaultLocale, isLocale, localeMeta (htmlLang, ogLocale, label, short)
  i18n/routing.ts             localePath, stripLocale, localeOf, localeAlternates
  i18n/dictionaries/pt.ts     the words in pt-BR; `Dictionary` is `typeof pt`
  i18n/dictionaries/en.ts     `en: Dictionary` (same keys, TypeScript checks)
  i18n/dictionaries/es.ts     `es: Dictionary`
  i18n/dictionaries/index.ts  getDictionary(locale)
  i18n/metadata.ts            pageMetadata(locale, path): title, description, alternates, Open Graph, Twitter
  i18n/params.ts              resolveLocale(params): the language of `[lang]`, or the 404
  app/(pt)/                   root layout + page + share.png of the default language
  app/(intl)/[lang]/          root layout + page + share.png of en and es (generateStaticParams)
  app/global-not-found.tsx    the 404 of the whole site (it reads the prefix in the browser)
  app/sitemap.ts              every page in every language, with hreflang
  components/language/        language-switcher.tsx (+ .module.css), flag.tsx, globe-land.ts
```

## How it routes

A static export has no server, so there is no `proxy.ts` to rewrite or redirect: each language is a page of its own,
written at build time.

- **Two root layouts** in route groups: `app/(pt)/layout.tsx` (the default, at the root) and
  `app/(intl)/[lang]/layout.tsx` (`generateStaticParams` from `prefixedLocales`, `dynamicParams = false`). Each one
  renders `<html lang>` of its language through `app/root-document.tsx`, so the exported HTML is right before any
  JavaScript runs.
- Going between `/` and `/en/` crosses root layouts: Next loads the new page in full. `/en/` ↔ `/es/` share the layout
  and navigate on the client.
- `/pt/` does not exist (the default has no prefix) and any other prefix is not exported: both answer the 404.
- With several root layouts there is no single layout for a `not-found.tsx`: `app/global-not-found.tsx`
  (`experimental.globalNotFound` in `next.config.ts`) is a whole document. It is exported once, in the default
  language, and `components/not-found-content.tsx` switches to the language of the prefix in the browser.

## Dictionaries

- Every word of the page is in the dictionary: copy, metadata, Open Graph and its image alt, `aria-label`s, the labels
  of the theme toggle and of the switcher. A string in a component is a bug.
- The type comes from `pt.ts` (`export type Dictionary = typeof pt`); `en.ts` and `es.ts` are annotated `: Dictionary`,
  so a missing or extra key fails the typecheck.
- Server components read `getDictionary(lang)` and pass words down as props. Client components receive strings
  (`ThemeToggle labels`, `LanguageSwitcher label`), never the whole dictionary; the 404 is the one exception (it learns
  its language in the browser).
- Lists (features, steps, questions) are arrays in the dictionary; what does not translate (the icons) lives in the
  component, in the same order.
- Names that do not change with the language (the product name, the URLs) are in `config/site.ts`, not in the
  dictionaries. Titles are composed: `${site.name}: ${meta.tagline}`.

## SEO

- `pageMetadata(locale, path)` gives every page: the canonical URL of its language, `alternates.languages` with every
  `htmlLang` plus `x-default` (the default language), `og:locale` with the others as `og:locale:alternate`, and the
  share image of the language with its alt.
- The share images are static GET Route Handlers (`share.png/route.ts` next to each root layout), written at build time
  as `out/share.png`, `out/en/share.png`, `out/es/share.png`. The `opengraph-image.tsx` convention is not used: its
  `alt` is a constant, and inside `[lang]` it does not receive the params of the layout in a static export.
- `sitemap.ts` lists each page once per language, each entry with the `xhtml:link` alternates of all of them.

## The switcher

`components/language/language-switcher.tsx`, with its CSS module:

- The globe spins slowly; the badge shows the flag of the current language. The panel opens out of the globe (a circle
  clip), the items come in one after the other and the flags roll in.
- On a choice: the highlight slides to the language, the flag flips like a coin with two pings, the globe speeds up and
  the badge turns; after 520 ms the navigation starts. The new page finds `app.locale-switch` in `sessionStorage` and
  the badge drops into place ("lands").
- The items are real `<a href hrefLang lang>`: a new tab, a middle click and the crawlers work as links.
- Keyboard: the button opens and closes, Tab walks the languages, Esc closes and gives the focus back. A click outside
  or the focus leaving closes it. `aria-expanded`, `aria-controls`, `aria-current` and `inert` on the closed panel.
- Less motion (the system setting or the appearance switch) stops the animations in `base.css` and the choice
  navigates at once.
- `variant="icon"` (header: the globe with a tooltip, the panel below) and `variant="labeled"` (footer, or the bottom
  of a phone menu: a pill with the name, the panel above). On a narrow screen the panel slides in to stay 16 px from
  the edge, and the circle still grows from the globe (`--dx`).
- Colors are the tokens (`currentColor`, `--foreground`, `--bg-base`, `primary`): it follows the theme and the accent.

## Add a key

1. Add it to `i18n/dictionaries/pt.ts`.
2. `npm run typecheck -w landing` points at `en.ts` and `es.ts`: write it there.
3. Read it with `getDictionary(lang).<group>.<key>` in a server component, or pass it as a prop to a client one.

## Add a language

1. `i18n/config.ts`: add the code to `locales` and its line to `localeMeta` (`htmlLang`, `ogLocale`, `label` in its
   own language, `short`).
2. `i18n/dictionaries/<code>.ts`: `export const <code>: Dictionary = { … }`, and register it in
   `i18n/dictionaries/index.ts`.
3. `components/language/flag.tsx`: its drawing in `flags` (TypeScript asks for it).
4. Nothing else: the static params, the alternates, the sitemap, the share images and the switcher read the list.
   `npm run build -w landing` and open `out/<code>/index.html`.

The default language is `pt` in `defaultLocale`, and the literal `'pt'` in the files of `app/(pt)/`. To change it,
change both (and the name of the group).

## Add a page

1. The component, taking `lang`, in `components/`.
2. Two routes: `app/(pt)/<page>/page.tsx` and `app/(intl)/[lang]/<page>/page.tsx`, each exporting
   `metadata`/`generateMetadata` as `{ ...pageMetadata(locale, '/<page>/'), title: <its title from the dictionary> }`
   and rendering the component.
3. The path in `PAGES` of `app/sitemap.ts`. The switcher keeps the page when the language changes (`stripLocale`).
