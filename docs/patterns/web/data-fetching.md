# Data fetching

The web app talks to the API through `@workspace/api-client`, a client generated by Orval from the OpenAPI document
the API exports, and caches with TanStack Query.

## The generated client

```
apps/api/openapi.json ──► packages/api-client/orval.config.ts ──► src/gen/endpoints/<tag>.ts   one file per tag
     (npm run api:openapi)        (npm run api:client)               src/gen/models/*.ts          DTO types and enums
```

`openapi.json` and `src/gen/` are **committed** and nobody edits them. After changing a route:

```bash
npm run api:openapi    # builds the API and writes apps/api/openapi.json (no database needed)
npm run api:client     # regenerates packages/api-client/src/gen
npm run typecheck      # shows what the new contract breaks
```

Every generated function returns `{ status, data, headers }`, typed as a union by status code from the responses the
API documents. The operation names are the controllers' names (`listNotes`, `archiveNote`); route params are an object
(`updateNote({ id }, body)`).

```ts
import { listNotes } from '@workspace/api-client/gen/endpoints/notes'
import type { NoteResponseDto } from '@workspace/api-client/models'
```

A wrong type in `gen/` is a wrong decorator in the API (a nullable string without `type: String`, for example): fix
the decorator, export, generate.

## Reading: `useQuery` + `unwrap`

`unwrap(promise)` turns "a value for every status" into "the data, or an `ApiError` with the API's `code`", which is
what TanStack Query expects:

```ts
export const useNotes = (params: ListNotesParams) =>
  useQuery({
    queryKey: queryKeys.notes.list(params),
    queryFn: () => unwrap(listNotes(params)),
    placeholderData: keepPreviousData, // paging and searching keep the last page on screen
  })
```

- Every key is in `apps/web/lib/query-keys.ts`, the resource first (`['notes', 'list', params]`), so one
  `invalidateQueries({ queryKey: ['notes'] })` refreshes every list and every note.
- Hooks of a resource live together (`components/notes/use-notes.ts`), not inside screens.
- Defaults (`lib/query-client.ts`): 30s fresh, no retry (an API error is an answer), no refetch on focus.

## Changing: `useApiMutation`

```ts
const archive = useApiMutation((id: string) => unwrap(archiveNote({ id })), {
  successMessage: 'Note archived',
  onSuccess: () => queryClient.invalidateQueries({ queryKey: queryKeys.notes.all }),
})
```

- A failure is an `ApiError`; a toast shows its message with the `code` as description, unless the code is in
  `silentCodes` because the screen shows it in place (a field error).
- `onSuccess` invalidates what changed. Optimistic updates are a choice per screen, not a default.
- A button that triggers a mutation shows `loading={mutation.isPending}`.

## States every screen has

Loading (a `Skeleton` with the shape of what comes), empty (an `EmptyState` with the way to start), error (the toast,
or inline), and the content. A list shows `aria-busy` while it refetches with the previous page on screen.
