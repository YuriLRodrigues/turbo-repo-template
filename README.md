# turbo-repo-template

A full-stack monorepo to start a product from: accounts, sessions, preferences, a design system and a small example
context are already done, tested and documented, so the first day goes to what makes the product different.

- **API**: NestJS 12 + Drizzle ORM 1.0 on Postgres, clean architecture, an embedded Postgres (PGlite) for development
  and tests, Swagger and an exported OpenAPI document.
- **Web**: Next.js 16 as a static export, TanStack Query over a client generated by Orval, react-hook-form + zod, a
  shell with a collapsible sidebar and a phone tab bar.
- **Landing**: a minimal product page with the basic SEO.
- **Design system**: neutral tokens on Tailwind v4, Base UI primitives with the shadcn anatomy, nine configurable charts
  on Recharts, light/dark themes with six accents, contrast-checked.
- **Tooling**: Turborepo, npm workspaces, ESLint (with the layer rules of the API), Prettier, Vitest, Playwright,
  husky + lint-staged + commitlint, Claude Code skills.

## Getting started

Requirements: Node.js 24 or newer (npm 12). Nothing else: no Docker, no database, no `.env`.

```bash
npm install
npm run dev
```

- API: <http://localhost:3500> (Swagger at <http://localhost:3500/docs>). It starts an embedded Postgres in
  `apps/api/.pglite/`, applies the migrations, and writes the e-mails (confirmation, password reset) to its log.
- Web: <http://localhost:3501>. Create an account and write a note.
- Landing: `npm run dev:landing`, then <http://localhost:3502>.

To use a real Postgres, copy `apps/api/.env.example` to `apps/api/.env`, set `DATABASE_URL` (the `docker-compose.yml`
in `apps/api` gives you one) and run `npm run db:migrate`.

## Scripts

| Script                                        | What it does                                                 |
| --------------------------------------------- | ------------------------------------------------------------ |
| `npm run dev`                                 | API + web in watch mode                                      |
| `npm run dev:api` / `dev:web` / `dev:landing` | one app                                                      |
| `npm run build`                               | every app and package                                        |
| `npm run preview` / `preview:landing`         | serves a static export like a static host                    |
| `npm run lint` / `lint:check`                 | ESLint in every workspace (fix / check)                      |
| `npm run format` / `format:check`             | Prettier (write / check)                                     |
| `npm run typecheck`                           | TypeScript in every workspace                                |
| `npm test`                                    | unit and integration tests of every workspace                |
| `npm run test:e2e`                            | the API over HTTP against a real (embedded) Postgres         |
| `npm run contrast`                            | WCAG contrast of every text token, both themes, every accent |
| `npm run api:openapi`                         | writes `apps/api/openapi.json` from the code                 |
| `npm run api:client`                          | regenerates `packages/api-client/src/gen` from it            |
| `npm run db:generate -- --name <name>`        | a migration from the schema diff                             |
| `npm run db:migrate` / `db:studio`            | applies migrations to `DATABASE_URL` / opens Drizzle Studio  |
| `npm run screenshots -w web`                  | pictures of every screen (API and preview running)           |

## Structure

```
apps/
  api/            NestJS + Drizzle: core, identity, notes (example), infra, HTTP, tests, OpenAPI export
  web/            Next.js static export: shell, auth screens, notes, charts gallery, settings
  landing/        Next.js static export: the product page
packages/
  ui/             design system: tokens, primitives, charts, appearance store, contrast check
  api-client/     Orval client + fetch mutator (refresh-and-retry, Web Locks across tabs)
  utils/          cn, money, numbers, dates
  config/         ESLint, TypeScript and Prettier presets
docs/
  business-rules.md   the numbered rules of the product: the contract
  patterns/           how the code is written (API and front), one short document per topic
.claude/skills/       project skills for Claude Code
```

Every workspace and the root have a `CLAUDE.md` with the conventions.

## How the pieces fit

1. A rule is written in `docs/business-rules.md`, implemented and tested in the API (`apps/api/src/domain`).
2. The route documents itself for OpenAPI; `npm run api:openapi` exports the document.
3. `npm run api:client` turns it into typed functions in `@workspace/api-client`.
4. The web app calls them through TanStack Query; the client renews the session by itself (a 401 refreshes once, and
   only one tab refreshes at a time).
5. Screens are built from `@workspace/ui`, whose tokens follow the look each person picks (saved in their account).

## Making it yours

Run the `rename-project` skill in Claude Code, or by hand:

1. Names: `package.json`, `apps/web/config/site.ts`, `apps/landing/config/site.ts`, `APP_NAME` in
   `apps/api/src/infra/env/env.ts` and `.env.example` (the product name in the e-mails, the boot banner and the
   OpenAPI title).
2. Keys: the refresh cookie (`apps/api/src/presentations/http/auth/refresh-transport.ts`), the storage keys of the
   appearance and the sidebar (`packages/ui`), the Web Lock name (`packages/api-client`).
3. Look: the values in `packages/ui/src/styles/tokens.css`, the fonts in the root layouts, `app/icon.svg` and
   `components/shell/brand.tsx`; then `npm run contrast`.
4. The example: keep the `notes` context as a reference until the first real context exists, then remove it (the
   skill lists every file).

## Conventions

- Conventional Commits (`feat(api): …`, `fix(web): …`), checked on every commit; lint-staged formats and lints the
  staged files of each workspace.
- Exact dependency versions.
- Code, docs and copy in English.
